# 0.5.0 — OCR 任务可见性与审核证据

- 状态：已发布至 GitHub
- 日期：2026-10-14
- 目标：让本地面板清楚区分 OCR 候选、已批准、真正执行中、结果待审核和最终应用。

## 新功能

- OCR 审核页按状态筛选任务，分别显示待判断、待执行 OCR、正在 OCR、待选结果、待应用和已完成数量。
- 每条任务显示原文件名、页码、候选原因和系统建议；可展开源图、原生 Blocks 与 OCR Blocks 对照。
- 面板发起 OCR 执行时显示真实的“正在 OCR”状态；同一审核任务不能重复并发执行。
- 审核按钮文案和完成提示明确区分批准执行、实际调用 OCR、选择 OCR 结果与应用最终决定。

## 修复

- 原页面只显示 `document_id` 和原因，难以判断对应的源文件；现在从运行产物读取原文件名。
- 原页面把已批准但尚未开始的任务显示为“待执行 OCR”，却无法单独查看真正运行中的任务；现在提供独立状态。

## 兼容性

- 解析算法、`ParsedDocument` Schema、CLI 和 Python API 不变。
- “正在 OCR”是当前本地 Web 服务的实时状态；服务重启后不保留执行中状态，也不监控 CLI 发起的自动 OCR。

## 验证

- 全量 Python 测试覆盖原文件名、源图、原生与 OCR Block 预览、执行中状态和重复执行防护。
- Vue TypeScript 检查及生产构建通过；Python wheel 包含最新页面资源。

## 已知限制

- OCR Provider 不提供页内百分比进度；面板显示执行中与完成状态，不显示 OCR 内部进度条。
- 复杂结果合并、页面排除与拒绝文档决定继续通过 CLI 完成。
