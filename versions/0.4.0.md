# 0.4.0 — 结构审核与结果对照

- 状态：已发布至 GitHub
- 日期：2026-10-11
- 目标：让用户在本地面板中完成常见结构审核，并直接比较基础解析与当前有效版本。

## 新功能

- 文件详情新增“结果对照”：展示基础版与当前有效版 Block，标出变化，按 Block 类型、页码筛选并分页浏览；不再局限于前 200 个 Block。
- 在文件详情顶部汇总有效 Block、质量警告、待审核线索和当前有效版本来源。
- 新增“结构审核”页签：识别跨页段落、跨页表格候选，展示候选 Block、审核原因和 PDF 原文件。
- 可在面板记录确认结构、修正段落文字、排除检索或拒绝文档；全部决定完成后定稿，并生成可追溯的最终有效版本。
- 审核操作复用 `StructureReviewStore`，与现有 CLI 共用任务、决定和定稿产物。

## 修复

- 解析失败但留下运行目录时，文件详情仍可显示失败 Manifest，不因缺少 `ParsedDocument` 报错。
- 结果页读取当前有效产物，而非始终显示基础版，因此 OCR 或结构审核完成后能看到更新内容。
- 已完成文件不再随 1.5 秒进度轮询反复读取完整详情，减少长期打开面板时的重复请求。
- 前端资源改用稳定文件名，清理旧构建缓存，避免 Python wheel 混入历史页面资源。

## 兼容性

- `ParsedDocument` Schema 保持 `1.0`，现有 CLI 与 Python API 不变。
- 面板仍只监听本机，保持单人使用；无需账号体系。
- 既有 0.3.0 批次和运行产物可继续查看。

## 验证

- 全量 30 项 Python 测试通过，覆盖结构候选、决定、定稿、版本对照，以及失败文件详情。
- Vue TypeScript 检查和生产构建通过；Python wheel 包含最新页面文件。
- 本地 HTTP 服务与示例文件流程验证通过。

## 已知限制与下一步

- 表格候选可确认、排除或拒绝文档；单元格级内容编辑尚未提供。
- 非 PDF 文件仍以解析后的 Block 为主要检查视图，尚无原版式预览。
- 浏览器页面需要连接正在运行的本地服务；更新代码后需要重启服务并刷新页面。
